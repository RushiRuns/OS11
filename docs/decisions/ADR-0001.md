# ADR-0001: Use better-sqlite3 over sql.js

## Status
Accepted

## Context
OS11 requires a local-first, high-performance database running in the Electron main process. The persistence engine must support synchronous queries to avoid async Promise overhead in the repository layer and guarantee transactional integrity.

We evaluated two primary SQLite libraries:
1. `better-sqlite3`: Synchronous, native C++ binding directly compiled for Node/Electron.
2. `sql.js`: WebAssembly port of SQLite that runs in-memory.

## Decision
We choose `better-sqlite3` as the sole database driver for OS11.

## Consequences
- **Positive**:
  - Synchronous API allows atomic, single-frame (<16ms) commits to disk.
  - Zero external cloud/server dependencies.
  - Full support for WAL (Write-Ahead Logging), FTS5 full-text search, and user-version pragmas.
- **Negative / Considerations**:
  - Native module requires compilation against Electron's Node ABI for target platforms. Mitigated via electron-builder.
