# ADR-0002: Choose Electron over Tauri for Desktop Layer

## Status
Accepted

## Context
OS11 requires cross-platform desktop capabilities (native windowing, system tray, local WebSocket sync server, OS keychain integration, background workers, and auto-updates).

Tauri was evaluated as an alternative for smaller bundle sizes and lower baseline RAM.

## Decision
We choose `Electron` paired with `electron-builder` and `electron-updater` for OS11.

## Consequences
- **Positive**:
  - Unified TypeScript ecosystem across main process, worker threads, and React renderer.
  - Mature ecosystem for OS keychain (`keytar`), native notifications, and differential auto-updates.
  - Seamless support for local Node.js WebSocket server and mDNS for Phase 2 companion sync without FFI overhead.
- **Mitigations for Electron Overhead (per PERFORMANCE.md)**:
  - Preloaded hidden window (<30ms warm open).
  - Virtualized lists (`@tanstack/react-virtual`).
  - Worker thread for full-text search indexing off the UI thread.
  - Strict bundle size budgeting (<150MB installed, <200KB gzipped initial JS).
